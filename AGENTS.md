## Визуальные правила

- Основные цвета: белый/молочный, графитовый, жёлтый только для акцентов.
- Минимализм, много воздуха, крупная типографика, реальные фотографии.
- Не использовать красные CTA, тяжёлые градиенты, дешёвые иконки, большие слайдеры и выдуманные стоковые лица.
- Единые радиусы, тени, размеры кнопок и плавные короткие анимации.
- Mobile-first, но desktop нельзя ухудшать ради мобильной версии.
- Соблюдать prefers-reduced-motion.

## Формы и Telegram

Все CTA должны использовать общий поток записи через EnrollmentProvider, а не создавать отдельные несвязанные формы.

Клиент отправляет JSON в POST /api/leads. Сервер проверяет данные и отправляет сообщение в закрытую Telegram-группу.

Нужные переменные:

- TELEGRAM_BOT_TOKEN
- TELEGRAM_CHAT_ID

Это секреты. Никогда не вставляй их в код, документацию, commit, GitHub Issue или чат. Локально они находятся в .env.local, в production — в Netlify Environment Variables.

После изменений форм проверить Hero, тарифы, квиз, карточку инструктора, контакты и финальный CTA.

## Правила изменения кода

1. В начале выполнить git status -sb.
2. Не удалять и не перезаписывать пользовательские файлы без причины.
3. Данные выносить в src/data, общие настройки — в src/config.
4. Не дублировать модальные окна и формы.
5. Для изображений использовать next/image, правильные sizes и ленивую загрузку, кроме LCP Hero.
6. Не запускать next build одновременно с next dev или next start: они используют один каталог .next и могут повредить локальную сборку.
7. Перед завершением выполнить pnpm test --run, pnpm lint, pnpm typecheck и pnpm build.
8. После публикации проверить публичный адрес, а не только успешный git push.

## Git и Netlify

Рабочая ветка — main. Push в origin/main запускает автоматическую публикацию Netlify.

Перед push убедиться, что .env.local не попал в Git, нет токенов и секретов, git diff --check не показывает ошибок, а проверки проекта прошли.
